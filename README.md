# WarOps — Remotion renderer

Renders `narration.json` (from the history-sourcer pipeline) into a finished
documentary MP4: Ken Burns motion on archival stills, timed portrait overlays
when people are named, caption bars, film grain, and SFX.

## Orientation rule (Lawal)

- Script **< 200 words** → **9:16 vertical** (1080×1920, shorts format)
- Script **≥ 200 words** → **16:9 landscape** (1920×1080)

Word count is taken from the narration segments. Override per render:

```
--orientation 16:9      # force landscape
--orientation 9:16      # force vertical
--word-threshold 150    # change the cutoff (default 200)
```

Vertical renders get their own layout: centered, larger portrait overlays,
bigger captions with more bottom clearance, and a 540×960 grain tile set
(`public/grain-portrait/`, generated by
`node scripts/gen_grain.mjs --w 540 --h 960 --dir grain-portrait`).

## Usage

```
python3 render.py narration.json --out video.mp4 [--skip-install] [--no-render]
```

- Downloads/normalizes each segment's licensed image into `public/images/`
  (segments with no licensed image get a dark archival placeholder plate).
- Downloads each person's portrait into `public/images/` (timed to the name).
- Copies narration MP3s into `public/audio/`, vendors SFX into `public/sfx/`.
- Writes `props.json` (segments + width/height), then `npx remotion render`.
- `--no-render` stops after writing `props.json` — useful for layout checks
  via `npx remotion still src/index.ts HistoryDoc still.png --props=props.json --frame=N`.

`src/index.ts` registers `src/Root.tsx`, whose `calculateMetadata` reads
`width`/`height` from props so the whole composition follows the orientation.

## Overlay templates (graphic cards)

`src/overlays.tsx` holds ten full-screen graphic-card templates in the
"data documentary" style — near-black plate, giant numerals, mono kickers,
red accents — with a studied motion language (hard cuts, slot-machine
odometer numbers, constant-speed fills) and separate 9:16 + 16:9 layouts:

| type       | use when the segment…                              |
|------------|----------------------------------------------------|
| `stat`     | centers on one headline figure (odometer number)    |
| `date`     | is about a date/moment ("22 JUNE 1941")            |
| `timeline` | spans a time range ending in a total (filling bar) |
| `bars`     | lists 2+ percentages (animated red bars)           |
| `table`    | lists 2+ name→figure pairs (ledger with total)      |
| `portrait` | names a commander + rank/role/fate (dossier card)  |
| `split`    | contrasts two figures side by side                 |
| `quote`    | has a striking line worth a full-screen pull-quote |
| `list`     | runs a numbered set of items (armies, waves…)      |
| `diagram`  | centers on a figure + a scale (distances, ranges)  |

Motion language (studied frame-by-frame from reference footage): elements
snap in with hard cuts, staged a beat apart; hero numbers roll like a
slot machine — red digits at constant speed, dead stop on the final white
number; rows appear one by one top to bottom; bars, rulers, and timeline
blocks fill left to right at constant speed; photos stay static; text never
types in letter by letter and nothing bounces or eases.

An AI **overlay director** decides per segment. Give it `OVERLAY_DIRECTOR.md`
(the playbook: catalog, rules, JSON schema) plus the segments
(`{index, text, duration}`, and any downloaded `portraits` with their
`file` paths for portrait cards). It returns `overlays.json`:

```
python3 render.py narration.json --overlays overlays.json --out video.mp4
```

Overlay segments skip the scene image and caption bar — the card IS the
visual; narration audio and the transition whoosh still play. Segments with
no overlay render as before. At most one overlay per segment; most segments
get none. Every figure on a card must come from the script (written-out
numbers may be converted to digits); the director never invents facts.

## Real video-clip backgrounds (`clips.py`)

Scenes can use genuine archival video clips instead of still photos.
`clips.py` hunts real footage (never AI — only the narration is AI) for
each narration segment, trying sources in order:

1. **Internet Archive** (`mediatype:movies`) — prefers public-domain /
   CC-licensed items, plus the Prelinger and US National Archives
   collections.
2. **Wikimedia Commons** (`filetype:video`) — license-filtered to public
   domain / CC0 / CC-BY / CC-BY-SA.
3. **YouTube** via `yt-dlp` — last resort, prefers known archival
   channels (British Pathé, Periscope Film, ...). YouTube items may be
   copyrighted, so the log warns every run and PD/CC sources are always
   tried first. (Note: YouTube's web player demands sign-in from
   datacenter IPs; the script uses the android player client, which
   still serves files anonymously. If that closes, YouTube is skipped
   for the rest of the run.)

Lawal's rules, baked in: no clip is reused within one documentary
(deduped by source id AND file hash), and the narration text is never
modified — search queries are derived read-only (proper nouns first,
but sentence-initial capitals don't count as proper nouns; remaining
words longest-first so content words beat filler adjectives; same
stopword list as `history-sourcer/segment.py`). YouTube gets a
shortened query (first 4 terms + "archival footage") because its fuzzy
search over-constrains on long queries.

Clips are shown exactly as they are — never upscaled or cropped
(Lawal's rule, same as portraits): `render.py` records each clip's
natural size via ffprobe (`clipNaturalW/H`), and the composition centers
it at that size on black, scaling down only if it's larger than the
frame. Small archival reels play at 3x their natural size (a 320×240
reel shows at 960×720), centered — Lawal found 1x too small. Still
capped to fit the frame and never cropped.

Behind those natural-size clips, a looping grid texture
(`public/grid_bg.mp4`, Lawal's asset, audio stripped) fills the frame —
`render.py` adds it as top-level `gridBg`/`gridFrames` props and the
composition cover-crops it behind the centered clip. It's a graphic
pattern, not archival content, so cover-cropping it is fine.

Automatic search is a *candidate finder*, not a decider — it WILL
return junk: title cards, modern documentaries with text overlays,
wrong-theater or wrong-era footage, heavy watermarks. The 3 check
frames per clip in `clip_frames/` exist so a human verifies every
clip: genuine historical footage, matching the segment's subject, no
AI-looking B-roll, no modern graphics. Reject and re-run (or curate
manually) until every clip passes the eyeball test.

YouTube download notes (learned 2026-09-24): datacenter IPs get
throttled — separate DASH streams (`bv*+ba`) get their connections
reset mid-download, while the combined progressive format
(`b[height<=720]/best`) serves fine. Some videos fail signature
deciphering at 720p but work at 480p/360p, so the script walks a
format ladder (720 → 480 → 360 → best). `--download-sections
"*00:00-05:00"` fetches only the head of the video (the trim takes 6s
from at most 10s in) instead of whole multi-hour compilations.
Internet Archive needs none of this — its downloads are fast and
unthrottled, which is another reason PD/CC sources come first.

For fully verified clips, manual curation is supported: download a
chosen PD/CC film, preview offsets with
`ffmpeg -ss <t> -i raw -frames:v 1 prev.jpg`, trim 6s slices with the
same codec settings `clips.py` uses (libx264 veryfast crf 20,
yuv420p, `scale='min(1280,iw)':-2`, `-an`), eyeball the check frames,
and hand-write `clips.json` (fields: `segment`, `file`, `source`,
`source_id`, `title`, `url`, `download_url`, `license`, `duration`,
`query`, `check_frames`). `render.py --clips` accepts it identically.

```
pip install yt-dlp          # once
python3 clips.py narration.json --out clips.json [--max-per-seg 1] [--segments 0,1,2]
python3 render.py narration.json --clips clips.json --out video.mp4
```

`render.py --clips` copies each segment's trimmed clip into
`public/clips/clip_XX.mp4` (manifest-aware: re-copied only when the
source URL changes, same `download_manifest.json` as images/portraits)
and passes `clipFile`/`clipFrames` to the composition. In
`src/HistoryDoc.tsx`, `ClipBackground` plays the clip with the same
fade-in + vignette as the Ken Burns stills and loops it to fill the
segment (stacked `Sequence`s — a native `loop` attribute does not loop
under Remotion's per-frame seeking). Captions, portraits, overlay
cards, SFX and film grain all play over video unchanged. Segments
without a clip render exactly as before.
